# Native Tools, PTY Execution, Output Filtering, and Permissions

## 1. Zero-Lua Native Built-In Tool Suite

All built-in tools live in `crates/tekvra-tools` and operate with zero Lua runtime initialization (`experimental.lua_plugins = false` by default and under `--no-plugins`):

- **Single-Editor Model Alignment**:
  - OpenAI GPT-5+, o-series, and Codex models receive `apply_patch` (`*** Begin Patch` / `*** Add File:` / `*** Update File:` / `*** Move to:` / `*** Delete File:` / `*** End Patch`) with whitespace-tolerant context seeking, deterministic per-path locks, and pre-mutation `tekvra-storage` snapshots.
  - Other model families receive `file_edit` + `file_write`.
- **Workspace Discovery & Code Outline**:
  - `file_read`, `file_glob`, and `file_grep` enforce output caps and skip `.git` as well as sensitive credential files (`.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa`, `id_ed25519`, `.npmrc`, `.pypirc`, `.netrc`) during scans, reporting `truncated` and `skipped_sensitive_files` explicitly.
  - `file_index` extracts structural symbol outlines with exact 1-based line ranges via native `tree-sitter` grammars (Rust, Python, Go, JavaScript, TypeScript/TSX, Bash).
  - `view_image` inspects workspace images (PNG/JPEG/GIF/WEBP) and returns a full base64 `ToolOutput::Image` payload; vision-capable models additionally receive a real `MessagePart::Image` attachment (a trailing user message, append-only) while other hosts see a concise text summary.
  - All read/search/index tools (`file_read`, `file_glob`, `file_grep`, `file_index`, `view_image`) route through the same permission ladder (`ToolAction::ReadWorkspace`), so explicit `deny` rules hold everywhere; the concurrent `batch` tool accepts only this read-only allowlist (run via `futures::future::try_join_all`, results kept in order) and rejects mutating tools with a validation error.
- **Interactive PTY Engine (`exec_command` & `write_stdin`)**:
  - Commands run inside a real pseudo-terminal (`portable-pty`) with a sanitized environment (`PATH`, `HOME`, `USER`, `LANG`, `TERM`, `TMPDIR` plus `AgentSettings` passthroughs/overrides).
  - Commands awaiting stdin or exceeding `yield_time_ms` return a live `session_id` receipt without restarting, allowing `write_stdin`, `resize`, `terminate`, and background completion notifications.
- **RTK-Derived Output Filter & `tool_output`**:
  - Terminal `\r` progress bars decode into single rows (`render_terminal`), ANSI escapes strip cleanly, and command-aware rules reduce build/test noise while **never** masking non-zero exit codes as success.
  - Full raw outputs are retained on disk and indexed in `state.db` for regex/line retrieval via `tool_output` and Raw/Filtered toggling in the TUI.
- **Isolated Monty Python `code` & Prompt-Cache-Stable MCP Gateway**:
  - `code` executes inside `monty` with zero direct host OS, filesystem, environment, or network access.
  - `ConfiguredMcpGateway` connects enabled `[mcp_servers.<name>]` entries over child-process `stdio` JSON-RPC 2.0 (`initialize`, `notifications/initialized`, `tools/list`, `tools/call`) and remote HTTP JSON-RPC 2.0 `POST` endpoints with bounded startup/call timeouts.
  - Connected MCP tools are listed (`mcp_list()`) and called (`await mcp_call(...)` / `mcp_call_sync(...)`) from `code`—and surfaced in `/mcp` and `mcpServerStatus/list`—without mutating top-level LLM `ToolDefinition` schemas when MCP servers connect or change.
  - MCP calls issued from `code` authorize through the same session permission ladder as top-level tools: in `Build` mode an uncovered call prompts interactively via `ApprovalCallback` (async, non-blocking the sandbox service loop) and fails closed when no approval host is attached; `deny` rules still win in every mode.
  - Server→client requests are routed, never dropped: `sampling/createMessage` (gated by `[experimental] mcp_sampling = true` + per-server `sampling = true`) answers through the session's `fast`-role model binding after an interactive approval prompt (headless/no-host → `-32603`), with usage attributed under `<rpc_id>_mcp_sampling`; `elicitation/create` flattens `requestedSchema` (string/number/boolean/enum) into interactive questions (headless → explicit `decline`); unknown methods answer `-32601`. Stdio servers are served by a dedicated reader task with per-call oneshot resolution (concurrent calls never serialize); HTTP responses stream through an incremental SSE parser with header-phase (60s) and per-chunk-idle (10s) bounds; `Mcp-Session-Id` is captured, echoed, and `DELETE`d on drop (`mcp_servers.<name>.session = false` opts out); `notifications/tools/list_changed` marks the catalog dirty and refreshes on the next gateway access.
- **Web Search (`web_search`)**:
  - One HTML search per call against a configurable endpoint (`agent.websearch_base_url`, default DuckDuckGo HTML Lite) through the SSRF-safe fetcher; results are parsed defensively (named `result__a`/`result__snippet` anchors, `/l/?uddg=` redirect decoding, the five named entities, tag stripping) with duplicate-host collapsing and a `max_results` cap of 1..=10 (default 8).
  - Authorized through the `webfetch` ladder class (deny rules and prompts apply to the search endpoint); zero results / unreachable / non-HTML endpoints return bounded errors naming the endpoint. Not `batch`-eligible.
- **Language Server Diagnostics (`lsp_diagnostics`)**:
  - Reads `path` (plus optional `[lsp.<id>]` key) and collects published diagnostics through a session-scoped `LspManager`: servers spawn over stdio JSON-RPC with `Content-Length` framing, run as read-only guests (`initialize` → `initialized` → `didOpen`/`didChange` only), and reuse across calls; `shutdown` on drop.
  - Collection waits a 500 ms quiet window bounded by a 5 s hard cap; output lines are `path:line:col [severity] message` (1-based). Authorized through the `ReadWorkspace` ladder for the target file. Bounded errors for missing `[lsp]` config, extension mismatch (`languages` filter), and startup crashes. Not `batch`-eligible.
- **Durable Subagent Tasks (`task`)**:
  - `task { prompt, role?, model?, background? }` spawns a steerable subagent session with its own rollout; `task { task_id, prompt, delivery? }` steers (`guide` default, `replace` preempts) via the same tool or `/tasks` (`Ctrl-X`).
  - `worktree: true` runs the child inside a dedicated `git worktree` (`<state_dir>/worktrees/<repo-slug>/<task_id>` on branch `tekvra/<task_id>`, baselined at the parent's HEAD) so concurrent tasks never race the parent tree; running outside a Git repository rejects the call before any session spawns.
  - Completion reports the branch plus a changed-file summary; merge-back is explicit: `task { task_id, merge: "merge" }` commits the worktree and merges `--no-ff` into the parent branch (conflicts abort cleanly with both trees intact), `merge: "discard"` removes the worktree and branch. With the opt-in `agent.allow_task_auto_merge = true` (global config, default disabled), `merge: "auto"` merges when clean and otherwise reports the conflict without touching the parent tree — it never resolves to `discard`. The `merge` verb authorizes the changed paths through the `WriteWorkspace` permission ladder (Build-mode prompts, `deny` rules win).
  - Nesting is depth-budgeted (`agent.subagent_max_depth`, default `1`): a subagent may spawn its own tasks only when its depth is still under the configured budget; `allow_subagents: false` (or exhausted budget) strips the `task` tool from the child roster entirely.

## 2. Consent-Driven Execution & Safety Model (No Kernel Sandbox)

Tekvra intentionally omits local OS kernel sandboxes (Landlock/seccomp/Seatbelt) and instead enforces transparent, inspectable consent boundaries:

1. **Platform Shell Subcommand Decomposition**: Every `exec_command` invocation is decomposed into constituent subcommands and evaluated independently — compound lines like `git status && rm -rf build/` never authorize as a single blob. Unix (`/bin/bash` or `sh`) payloads parse via `tree-sitter-bash` across `&&`, `||`, `;`, `|`, subshells, `$()`, and redirections. Windows (`pwsh.exe`/`powershell.exe -Command`) payloads parse with a native PowerShell lexical decomposition (`tekvra_tools::powershell_syntax`): statements split on `;`, newlines, `|`, `&&`, `||` (including inside `(...)`); `{...}` script blocks stay opaque and turn destructive if they contain cmdlets like `Remove-Item`/`Set-Content`/`Invoke-Expression`; call operators on literal paths decompose while `& $var`, `iex`, `$()`, splatting, and nested `-Command` payloads are dynamic; `>`, `>>`, `2>`, `*>` redirect targets surface as write targets (`2>&1` merges are inert). Dynamic or unparseable constructs on either shell allow `Once`-only approval (fail-safe); PS read-only allowlisting (e.g. `Get-ChildItem`, `Select-String`, `git status`, numeric ranges) is case-insensitive.
2. **Execution Modes**:
   - `Plan` / `ReadOnly`: Read-only workspace inspection and (`Plan` only) `plan` updates; file writes and non-read-only commands are rejected before touching disk.
   - `Build`: Workspace file mutations allowed; unapproved shell commands, external paths, `webfetch`, and MCP calls prompt.
   - `Auto`: Skips routine unmatched prompts within workspace boundaries while enforcing `deny`/`ask` rules, external path prompts, and `Once` prompts for dynamic scripts.
   - `Yolo`: Skips interactive prompts while **unconditionally enforcing explicit `deny` rules**.
3. **Scoped Approval Ladders**: Prompts present narrow-to-broad scopes (`ExactCommand` -> `CommandPrefix` rungs, `PathPrefix`, `UrlPrefix`, `McpTool`) across `Once`, `Conversation`, `Project`, and `Global` lifetimes. Broad grants (such as 1-token `cargo *` or paths outside `$HOME`) require secondary confirmation (`confirmed_broad = true`).
4. **SSRF-Safe `webfetch`**: Resolves DNS and validates every redirect hop to block loopback (`127.0.0.0/8`, `::1`), link-local/cloud metadata (`169.254.0.0/16`, `fe80::/10`), and private RFC1918/ULA ranges unless allowlisted in global config.
5. **Project Memory (`memory_save`)**: Appends one dated entry to the per-project `MEMORY.md` under `<state_dir>/memory/<project-slug>/` (8 KiB per-entry / 256 KiB per-file caps, errors name the limit). Authorized through the new `ToolAction::UpdateMemory` ladder arm: an explicit `allow` rule for `memory_save` grants it everywhere; `ask` rules prompt; in Build/Yolo the call prompts interactively (single `SessionTool` rung — "This session"); `Auto` grants within the workspace; `ReadOnly`/`Plan` deny by default with an actionable message. Explicit `deny` rules for `memory_save` win in every mode. Interactive surfaces: `/memory` (print path + content) and `tekvra memory --append TEXT` (stateless).
